Selective Bloom
共通基盤 実装計画

明るさだけでBloom対象を決める現行方式を改め、指定したGPU/CPUパーティクル、GameObject、SkinnedModel、Sprite、Ribbonだけを発光させるためのエンジン共通実装計画です。

作成日: 2026-08-11 / 対象プロジェクト: GameTemplate / 文書種別: 実装前設計・受け入れ基準

目的構造共通データAPI工程変更箇所検証リスク完成条件

1. 目的と完成像

対象を明示的に選択

画面上の輝度ではなく、Materialの設定によってBloom Maskへ出力するかを決定します。白い床や空などは明るくてもBloomしません。

エンジン共通機能

パーティクル専用フラグにはせず、GameObject、SkinnedModel、Sprite、Mesh、Ribbonが同じEmissiveSettingsを利用します。

Pure GPUを維持

GPUパーティクルのBloom属性もGPU常駐データとして扱います。粒子情報、生存数、発光値のCPUリードバックは追加しません。

既存資産との互換性

既存MaterialとJSONはBloom無効を既定値として読み込み、見た目を変えません。Selective Bloomは明示的に有効化した資産だけへ適用します。

非目標: ライトとして周囲を照らすGlobal Illuminationではありません。これは画面空間の発光ぼかしです。実ライトを生成するParticle Light Rendererは別機能として扱います。

確定仕様: Deferred GBuffer

既存GBufferにはRT3 Emissiveが存在しますが、現在はR8G8B8A8_UNORMです。新しいGBuffer RTは増やさず、RT3だけをR16G16B16A16_FLOATへ昇格します。RGBへemissiveColor * intensity、AへbloomContributionを格納します。FP16は本仕様のRGB上限64とContribution 0～1を十分な精度で保持でき、ログエンコードは使用しません。

GBuffer現行変更後判断
RT0 AlbedoRGBA8 UNORM変更なし非HDR属性
RT1 NormalRGB10A2 UNORM変更なし既存精度を維持
RT2 MaterialRGBA8 UNORM変更なしRoughness/AO
RT3 EmissiveRGBA8 UNORMRGBA16 FLOATHDR値を無損失で保持

1920×1080でRT3の増分は約7.9 MiB（4 bytes/pixel増）です。新規GBuffer RTを1枚追加する案よりRTV/SRV数とGeometry Pass帯域を抑えます。

確定仕様: Deferred → Forwardの書き込み順序

  1. Bloom Maskを黒でClearし、Scene ColorとBloom MaskをRENDER_TARGETへ遷移。
  2. 現行のDeferred Light PassはComputeではなくGraphics Fullscreen Pixel Shaderなので、2 RTVを同時Bindし、Scene Colorと不透明物のBloom Maskを上書き出力。
  3. Scene ColorとBloom MaskをRTV状態のまま維持し、Forward GameObject、Sprite、Particleを描画。Forward側はBloom Maskへ独立Blendで合成。
  4. Forward終了後に両RTをPIXEL_SHADER_RESOURCEへ遷移し、Bloom MaskをDownsample/Blurへ渡す。
バリア方針: Bloom Maskは生成中にUAVへしません。Deferred/ForwardともRTV書き込みに統一するため、毎フレームのRTV↔UAV往復はありません。Blur入力へ移る時のRTV→SRV遷移だけを行います。

確定仕様: BlendMode別Bloom Mask合成

PSOはIndependentBlendEnable=TRUEとし、RT0は既存Blend、RT1は下表の専用Blendを使用します。シェーダーはRT1 RGBへ常にemissive * saturate(alpha) * bloomContributionという事前乗算値を出します。

Scene BlendRT1 Src / Dest / OpBloom意味論
AlphaONE / INV_SRC_ALPHA / ADD透明度に従うPremultiplied Alpha
AdditiveONE / ONE / ADD光エネルギーを加算
Screen / Lighten / ColorDodgeONE / ONE / ADDBloom Maskでは安定した加算へ統一
Multiply / Subtractive / Darken / ColorBurnONE / ONE / ADDBloomはSceneの色演算と分離した発光エネルギー。全Material共通でEnabled=falseが既定

Bloomは「周囲へ漏れる光」であり、Scene ColorのMultiply等をBloom Maskへそのまま適用しません。非発光MaterialはBlendModeに関係なくenabled=falseとNoBloomWrite PSOによりRT1へ書きません。

Bloom無効Materialのコスト方針

Bloom機能全体がONのときはRTを2枚Bindし、MaterialごとにBloomWriteとNoBloomWriteを選びます。無効Material用PSOではRT1のRenderTargetWriteMask=0とします。Bloom機能全体がOFFのときは、Deferred Light Pass、Forward Object、Particle、RibbonをSV_TARGET0だけの単一RT PSOへ切り替え、Bloom Mask RTをBegin/Bind/Endしません。Material定数による動的分岐や黒の書き込みは行いません。

フレームバッファリングとMSAA前提

  • 現行SwapChainは2 Bufferですが、Scene/Bloom/GBufferは単一オフスクリーンRTです。PostDraw()が毎フレームFence完了を待つため、現状は単一RTを安全に再利用できます。
  • 将来Fence待ちを廃止して2～3 frames-in-flightへ移行する場合、Bloom Mask、Scene Color、Blur Ping-Pong、GBufferをFrame Contextごとに複製することを必須条件とします。
  • 現行は全RTがSampleDesc.Count=1でMSAAなしです。今回の実装にResolve Passは追加しません。
  • 将来MSAAを有効化する場合はScene ColorとBloom Maskを同じSampleCountで生成し、両方を個別にResolveしてからPostProcessへ渡します。片方だけResolveする構成は禁止します。

3. 共通Materialデータ設計

struct EmissiveSettings
{
    bool enabled = false;
    EmissiveSource source = EmissiveSource::Uniform;
    Vector3 color = { 1.0f, 1.0f, 1.0f };
    float intensity = 1.0f;
    float bloomContribution = 1.0f;
};
値意味推奨範囲
enabledBloom Maskへの出力を許可false / true
sourceUniform／BaseTextureMask／EmissiveTexture既定はUniform
color発光色。Base Colorと独立各成分 0～16
intensity発光そのもののHDR強度0～64
bloomContributionBloom Maskへ渡す割合0～1
既定値規則: 全BlendModeでenabled=false、bloomContribution=1.0に統一します。Contributionは有効化した後の強さであり、BloomのOn/Off判定には使用しません。Multiply/Subtractive/Darken/ColorBurnも既定ではBloomせず、明示的にEnabledへ変更した場合だけContribution 1.0で発光します。BlendMode別の暗黙的なContribution上書きは実装しません。

CPU設定APIではNaN/Infを検出して設定を拒否し、直前の正常値を維持します。GPU側ではisfinite()相当で検出し、異常値を0へ置換した後、RGBをclamp(0, 64)、Alpha/Contributionを0～1へ制限します。GPUについて「拒否」という表現は使用しません。

Emissiveテクスチャとの関係

現行実装を確認した結果、GBuffer RT3は予約されているだけで、GBufferPass.PS.hlslは常に黒を書き、Light Passも宣言したEmissive Textureを使用していません。Material/Model ImporterにもEmissive Map読込は存在しないため、既存の質感付きEmissive資産はありません。Assimp外部ヘッダーの定数は実装済み機能とは見なしません。

将来の空間変化を後付けにしないため、次のSourceを最初から型とJSON Schemaへ定義します。

SourceEmissive計算用途
Uniformcolor * intensity単色発光、既定
BaseTextureMaskbaseTexture.rgb * color * intensityParticle/Spriteの形状を発光Maskに使う
EmissiveTextureemissiveTexture.rgb * color * intensityGameObjectの窓・回路など部分発光

専用Emissive TextureはLinear色空間で読み、Base Color Textureとは別SRVとしてMaterialへ保持します。未設定・ロード失敗時は黒へフォールバックし、不正descriptorをBindしません。最終Maskは上記RGBへAlphaとbloomContributionを掛けます。

JSON共通表現

"emissive": {
  "enabled": true,
  "source": "EmissiveTexture",
  "texture": "./Resources/textures/sign_emissive.png",
  "color": { "r": 0.2, "g": 0.7, "b": 1.0 },
  "intensity": 8.0,
  "bloomContribution": 1.0
}

このブロックをParticle Renderer、GameObject Material、Sprite Materialで共通利用します。存在しない旧JSONはenabled=falseとしてMigrationします。

GPU timestamp・性能ゲート結果: Maskを含むScene区間、Source Extraction、水平Blur、垂直Blur、Compositeへ10点timestamp queryを実装し、前フレームFence完了後だけReadbackします。RTX 3060 Laptop GPU、1920×1080、Release、VSync OFF、初期60フレーム除外、300サンプルの正式比較ではSelective 0.657 ms、Legacy 0.617 ms、差+0.040 ms/+6.47%で+1.00 ms/+10%予算に合格しました。Particle Material Bloom有無のMask区間差は+0.006 msで+0.35 ms予算に合格、Bloom OFF時Blurは0、固定VRAM増分23.730 MiBで32 MiB予算に合格です。導入前バイナリが無いため、Bloom無効時とCPU frameの「導入前との差」だけは未計測として明示します。

8. リスクと対策

MRT帯域増加

GBuffer RT3をRGBA16Fへ昇格し、Bloom MaskもRGBA16Fとします。Bloom無効PSOはRT1 WriteMask=0、有効時だけ書き込みます。32 MiBとGPU時間の性能予算を超えた場合はMask解像度を下げます。

Deferred/Forward差異

同じMaterial APIでも出力経路が異なります。共通HLSL関数でEmissive計算を一元化し、色差を防ぎます。

透明物の順序

透明ParticleのMaskも同じAlphaを使い、背景を黒で上書きしないBlend Stateを設定します。

HDR異常値

RGBの単純saturateは禁止しつつ、NaN/Inf拒否と上限Clampを必須にします。

既存Bloomの見た目変更

Selectiveを新Modeとして導入し、移行期間だけLegacy Luminanceを選択可能にします。最終既定値はSelectiveです。

PSO不一致

RT数・FormatがPSOと描画先で一致しないとD3D12エラーになります。PSO keyへBloom MRT構成を含め、自動検証します。

単一RTとFrames-in-flight

現行は毎フレームFence待ちなので単一RTが安全です。待機を外す変更と同時にFrame Context別RTへ移行し、単独で非同期化しません。

将来のMSAA

現状SampleCount=1です。MSAA導入時はScene/Maskを同じSampleCountで生成し、両方Resolveする設計レビューを必須にします。

PSO順列増加

Material Bloom On/OffのMRT 2系統に、Bloom機能全体OFF用の単一RT系統を加えます。Pipeline Manager初期化時に全54順列を生成します。Editor切替時の同期生成は禁止し、SB-16で監視します。

Emissive Texture

現行資産にはEmissive Map経路がありません。新規Source列挙でUniform/BaseTexture/専用Textureを分離し、専用TextureはLinear読込、失敗時は黒とします。

9. Definition of Done

  • 指定したParticle、GameObject、SkinnedModel、SpriteだけがBloomする。
  • 非対象の高輝度オブジェクトはBloomしない。
  • Particle Sprite、Mesh、RibbonのPure GPU経路を維持し、GPU→CPUリードバックが0である。
  • 共通EmissiveSettingsと共通JSON形式を使用している。
  • Editorから設定し、保存・再ロードできる。
  • Bloom無効時に不要なGPU Passを実行しない。
  • Debug/Releaseビルド、D3D12 validation、Resize耐久、Scene切替耐久が合格する。
  • 既存資産は明示的に有効化しない限り表示が変わらない。
  • Deferred不透明とForward半透明が同一画素で重なるSB-11に合格する。
  • 全BlendModeの既定値はEnabled=false、Contribution=1.0で統一され、BlendMode依存の暗黙上書きがない。
  • Uniform／BaseTextureMask／EmissiveTextureが実装され、専用Emissive Textureの空間変化を保持する。
  • 全PSO順列が描画開始前に生成され、EditorでBloomを切り替えても同期生成・コンパイルが発生しない。
  • PSOプリウォーム増分がCacheなし初回+300 ms以下、Cacheあり通常起動+75 ms以下である。
  • 1080p Release計測で、Bloom無効時+0.20 ms/+3%以下、有効時Legacy比+1.00 ms/+10%以下、追加VRAM 32 MiB以下を満たす。
  • 32 MiBはBloom基盤Render Targetだけの予算であり、Emissive Textureアセットは別枠Texture Budgetとして分離計測・報告される。
推奨着手順: 共通データ → HDR Bloom Mask → PostProcess入力変更 → Particle対応 → GameObject/Skinned/Sprite対応 → Editor/JSON → 最適化、の順で進めます。Particleだけ先行して専用実装すると、GameObject対応時にPSO・Material・JSONを作り直すため避けます。
