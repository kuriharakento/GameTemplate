1. 実装概要

Pure GPUシミュレーション

固定長GPU pool、dead-slot atomic claim、GPU内alive compact、4 byte非同期completion recordにより、粒子payloadを毎フレームCPUへ戻さず更新します。

GPU-driven描画

Sprite/Mesh/Ribbonの描画数をGPUで生成し、Indirect Drawで発行。Ribbonはpersistent IDによるsortとribbonId groupingを行います。

Niagara型モジュール基盤

44モジュールをdescriptor registryへ登録。phase、priority、parameter schema、CPU/Pure GPU capabilityを宣言し、CompiledEmitterへコンパイルします。

GPU event chain

Spawn/Death eventをGPU bufferへ記録し、後続emitterが同一effect・同一frame内で直接消費します。velocity/color継承にも対応します。

Editor / Serialization

全44モジュールの追加・編集・JSON v2往復を整備。旧JSONのmigration、値域・参照順・enumの厳密validationを追加しました。

互換fallbackと診断

Pure GPU非対応構成はHybrid/CPUへ明示的にfallback。CPU/GPU時間、転送量、descriptor数、実行経路をCSVへ記録します。

3. 実装した機能

SpawnRate / Burst / dead-slot再利用

ParticleSpawnPrepare.CS.hlslがrate accumulator、burst delay/interval/loop、event spawn数をGPU emitter stateへ保存します。低FPSや大きなdeltaTimeでも、寿命内に残るRate birthだけを保持し、sub-frame ageを付けます。更新CSは既存粒子を先に死亡判定するため、同一dispatchで空いたslotをすぐ再利用できます。

主要Spawn Shape

Point、Sphere、Circle、Box、Cone、LineをGPU生成。inner/outer radius、surface/edge、arc、box size、cone height、line endpoints、surface direction初速をconstant bufferへコンパイルします。

Sprite / Mesh

GPU compact bufferをSRVとして参照し、GPU生成のdraw argumentsで描画します。Spriteはbillboard/2D alignment、Meshはinstance indirect描画に対応します。

Ribbon / Multi-ribbon

alive粒子を(ribbonId, persistentId)でbitonic sortし、6頂点の独立segmentとgroup境界の縮退要素をGPU生成します。AssignRibbonId(N)で1 emitter内にN本のRibbonを構築します。外部CPU source transformを使うMultiSourceRibbonは互換Hybrid経路です。

GPU Event / Sub-emitter

Spawn=0、Death=1、Collision=2のevent型を定義。現在Pure GPUで生成するのはSpawn/Deathです。source emitterはchildより前のindexである必要があり、probability filter、velocity scale、color継承をGPUだけで処理します。

Packed GPU module program

モジュール列を固定recordのprogram bufferとcurve/gradient用LUTへpackし、ParticleComputeが順番に解釈します。CPUでは同じdescriptor列をCompiledEmitter::Executeがphase別に実行します。

容量変更と失敗時rollback

SetMaxParticlesは1〜1,000,000へclampし、新しいGPUSimulatorと21個のdescriptorを先にtransactional確保します。初期化が成功した場合だけ旧Simulatorと交換し、枯渇・resource生成失敗時は旧capacityを保持します。Sprite/Meshはserializeされた容量を利用でき、GPU sortを使うRibbonだけ65,536上限です。

Renderer交換・Effect削除のGPU安全性

交換されたRenderer/Simulator/Effectは即時deleteせず、次にsubmitされるfence値と一緒に退避します。GetCompletedFenceValue()が到達してから解放するため、GPUが旧bufferを参照中でもuse-after-freeになりません。Effect poolは同名2個・全体16個までに制限し、異なる名前のone-shot Effectによるdescriptor保持の無制限増加を防ぎます。

6. EditorとJSON

  1. ParticleTestSceneでParticle Editorを開く。
  2. Effect → Emitterを追加し、Simulation ModeをGPUへ設定。
  3. Module追加画面からSpawn/Update moduleを追加。registry schemaに応じてproperty UIが表示されます。
  4. Sprite/Mesh/Ribbon rendererを選択。Ribbonを複数化する場合はAssignRibbonIdとgroup countを合わせます。
  5. Event childはsourceより後へ配置し、source indexとtriggerを設定。

9. Dynamic Input、resource安全性、TextureSheet

Dynamic Input

RegistryでdynamicInput=trueのparameterは、Constant、RandomRange、Curve、EmitterParameterを選択できます。EditorのEmitter Parametersで型付きparameterを作成し、Dynamic Inputsからmodule parameterへbindingします。型が一致しないparameterは候補に表示されません。

"dynamicInputs": [{
  "module": "SpawnRate",
  "parameter": "rate",
  "type": 0,
  "mode": 3,
  "emitterParameter": "User.SpawnRate",
  "fallback": 10.0,
  "minimum": 0.0,
  "maximum": 1000000.0,
  "keys": []
}]

RandomRangeはseedから決定論的に評価され、Curve keyは0〜1へ制限されます。同時刻keyは置換され、0除算しません。Bindingはcompiled emitterのlayout hashへ含まれ、CPU実行前にmoduleへ適用されるため、同じmodule getterをPure GPU定数／program packも参照します。未実装parameterはRegistryで公開されず、API・JSON・Editorで拒否されます。

Descriptorとresource寿命

  • SrvManager::TryAllocate/TryAllocateRangeは枯渇をReleaseでも安全に返します。
  • GPU emitterの21 descriptorは一括transactionで、途中失敗時は全て巻き戻します。
  • 最大数変更は新Simulator初期化成功後だけswapし、失敗時は旧capacityで継続します。
  • Renderer/Simulator/Effectの遅延破棄はフレーム数ではなくcompleted fence値で判定します。
  • Effect poolは同名2個・合計16個を上限とし、超過分はfence完了後に実破棄します。
  • PurgeEffectPools()によりScene遷移やEditor試験後の明示回収が可能です。
  • Default heap bufferとMesh indirect argumentsはCOMMONで生成し、利用直前に明示transitionします。

TextureSheetと容量

Hybrid GPU描画ではParticle::spriteIndexとcolumns/rowsからConvert CSがUV offset/scaleを計算します。Ribbonだけがbitonic sort由来の65,536上限を持ち、Sprite/Meshにはこの制限を適用しません。

Collision GPU event: producerが未実装のため、OnCollisionはEditor候補から除外し、JSONとAPIでも拒否します。無言でOnDeath等へ置換しません。

10. Selective Bloom

Scene Colorの輝度ではなく、明示的に指定したParticle／GameObject／SkinnedModel／SpriteだけをRGBA16F Bloom Maskへ出力します。DeferredはGBuffer RT3、ForwardはScene Color + Bloom MaskのMRTを使い、Particleは全9 BlendModeについてBloom On/Offを起動時にプリウォームします。

Particle EditorとJSON

EmitterのRenderer欄にあるSelective BloomでEnabled、Source、HDR Color、Intensity（0〜64）、Bloom Contribution（0〜1）を設定します。SourceはUniform、Base Texture Mask、Emissive Textureの3種類です。専用TextureはLinear色空間でロードされ、不正パスまたは未設定時は黒へフォールバックします。

黒フォールバック: Emissive未設定時は専用資産Resources/textures/emissive_black_1x1.pngを使用します。従来のblack.pngは実画素が黒ではなかったため、発光用途から完全に分離しました。TextureManagerは1×1画像では生成不能なMip生成を行わず、元画像を直接アップロードします。Particle Sprite／Mesh／Ribbon、2D Sprite、Model、SkinnedModelの全経路で同じフォールバックを使用します。

"emissive": {
  "enabled": true,
  "source": "EmissiveTexture",
  "color": { "r": 0.25, "g": 1.5, "b": 4.0 },
  "intensity": 8.0,
  "bloomContribution": 0.8,
  "texture": "./Resources/circle2.png"
}

GameObject API

EmissiveSettings glow;
glow.enabled = true;
glow.source = EmissiveSource::BaseTextureMask;
glow.color = { 0.2f, 1.0f, 4.0f };
glow.intensity = 8.0f;
glow.bloomContribution = 0.75f;
gameObject->SetEmissiveSettings(glow);

通常モデルとSkinnedModelは同じAPIを使用します。AssimpのEmissive Mapは専用Linear SRVとして自動読込されます。GameObject JSONではmaterial.emissiveへ保存され、旧JSONはBloom無効としてロードされます。

入力安全性: CPU APIは無効なEmissiveSourceまたはNaN/Infを含む設定全体を拒否し、直前の正常値を維持します。有限な範囲外値だけをColor 0〜16、Intensity 0〜64、Contribution 0〜1へClampします。GPU側でも有限値検査とClampを再実行します。

GPU粒子テストJSON

Resources/json/particles/tests/selective_bloom_pure_gpu_test.jsonは65,536個のPure GPU Spriteを生成し、Base Texture Mask、HDR Intensity 8、Additive BlendでSelective Bloomを確認します。Particle EditorのLoad...からtests/selective_bloom_pure_gpu_test.jsonを選択してください。従来表示の比較にはBloom無効のtests/pure_gpu_sprite_test.jsonを使用します。

頂点伸長・画面全体を覆う粒子の防止

GPU変換時にNaN/Infだけでなく極端な有限座標・Scale・Rotationを除外します。Sprite頂点シェーダーはビルボード四隅のclip-space Wをインスタンス単位で検査し、1つでもカメラ近面を跨ぐ場合は四頂点を同時に画面外へ棄却します。これにより透視除算で単一三角形が画面全体へ伸びる一時的な描画破損を防ぎ、CPU readbackは追加しません。

RT・PSOの防御

RenderTextureはSRV index 0も正規descriptorとして解放します。不正BlendModeは設定時に拒否され、PSO取得時にもBloom On/Off状態を維持したAlphaへフォールバックします。

通常2D SpriteはSpriteNoBloom.PS.hlslの1 RT PSO、Selective Bloom描画だけはSprite.PS.hlslの2 MRT PSOを使用します。これにより未BindのSV_TARGET1へ出力するD3D12警告を発生させません。100回リサイズ試験結果はResources/test-results/particles/selective_bloom_resize_test.txt、300秒連続試験結果はselective_bloom_300s_test.txtに出力されます。いずれも正しいKCE_D3D12_CAPTURE_ERRORS=1でWarning/Error 0を確認済みです。

2D Sprite

sprite->SetEmissiveSettings(glow);
sprite->SetEmissiveTexture("./Resources/glow_mask.png");
// Scene ColorとBloom Maskの2 RTVがBindされたForward区間で呼ぶ
sprite->DrawSelectiveBloom();
描画位置: 通常のDraw()はポストプロセス後のUI用でBloom対象外です。Bloomさせる2D SpriteだけをForward区間でDrawSelectiveBloom()により描画してください。

GPU側ではNaN/Infを0へ置換し、Emissive RGBを0〜64、Contributionを0〜1へ制限します。Bloom機能ON中の非対象ParticleとForward ObjectはRT1 WriteMask=0のPSOを使用します。Bloom機能全体をOFFにすると、Deferred Light Pass・Forward Object・Particle・Ribbonは単一RT専用PSOへ切り替わり、Bloom Mask RTのBegin/Bind/EndとBlur/Compositeを省略します。自動試験では環境変数KCE_BLOOM_ENABLED=0でこの経路を固定できます。

GPU timestamp診断
