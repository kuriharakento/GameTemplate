# TASK-06: ビューごとに正しい行列で描けるようにする（定数バッファの割り当て方式の変更）

- 対応: `SEQUENCER_PLAN.md` 4.3 の積み残し（Phase 4 の不具合修正）
- 作業ブランチ: `codex/task06-view-constants`（親・engine の両方に作成済み）
- 前提: `docs/codex/ONBOARDING.md` を先に読むこと（**「6. コミット」に履歴を書き換えないルールを追加した**）

---

## 1. なぜやるか

Phase 4 で `RenderView` を導入し、1フレームに複数の視点（本編、中継映像、カメラプレビュー、反射）を
描けるようにした。**しかし実際には正しく描けない。**

原因は定数バッファの持ち方にある。

- `Object3d` / `SkinnedObject3d` は WVP 用の定数バッファ（`wvpResource_`）と
  カメラ用の定数バッファ（`cameraResource_`）を**オブジェクトごとに1つずつしか持たない**
- 描画のたびに CPU からそこへ行列を上書きし、GPU 仮想アドレスをバインドしている
- コマンドリストに積まれるのは「アドレス」だけで、GPU が実際に読むのは実行時
- よって本編とサブビューが同じオブジェクトを描くと、**GPU の実行時点では最後に書いた値しか残っておらず、
  両方のビューが同じカメラの行列で描かれる**

サブビューをまだ誰も使っていないので表面化していないだけで、
Phase 11（ステージモニターへの中継映像）や床の平面反射を作った瞬間に破綻する。
**その前に直す。**

---

## 2. 方針：フレーム単位のリニア割り当て

「描くたびに、そのフレーム専用の新しい定数領域を切り出して書き、そのアドレスをバインドする」方式に変える。

```
フレーム開始 → 割り当て位置を先頭に戻す
描画ごと     → 256バイト境界で領域を切り出す → CPUで書き込む → そのGPUアドレスをバインド
```

同じオブジェクトを2回描けば2つの別領域に書かれるので、ビューごとに正しい行列が残る。

### 2.1 追加するもの

`engine/graphics/` 配下に、フレーム単位のアップロード用リングバッファを1つ作る
（名前は例: `FrameConstantAllocator`）。

- UPLOAD ヒープのバッファを1本確保し、常時 Map しておく
- `Allocate(size)` は 256 バイト境界に切り上げて領域を返す
  （CPU 書き込みポインタと `D3D12_GPU_VIRTUAL_ADDRESS` の組）
- `BeginFrame()` で割り当て位置を戻す

### 2.2 **最重要：GPU がまだ読んでいる領域を上書きしないこと**

割り当て位置をフレーム頭で戻してよいのは、**前フレームのコマンドの実行完了を待っている場合だけ**である。

- まず `DirectXCommon::PostDraw()` がフェンスで GPU 完了を毎フレーム待っているかを**コードで確認すること**
- 待っているなら、容量1本・毎フレーム先頭に戻す、でよい
- 待っていない（フレームを重ねて実行している）なら、フレームごとに領域を分けること
  （バッファを「同時に実行されうるフレーム数」ぶんに区切り、フレーム番号で使い分ける）
- どちらだったかを**報告に必ず書くこと**

ここを間違えると、D3D12 のエラーは出ないまま「たまにチラつく」形でしか現れない。
デバッグレイヤーでも検出できない種類の不具合なので、推測で済ませないこと。

### 2.3 容量不足のとき

- 容量を超えたら assert で落とさず、`Logger::Log(..., Error)` を出して
  そのオブジェクトの描画をスキップする
- 初期容量はオブジェクト数の見込み × ビュー数に余裕を持たせた値にし、
  名前付き定数にすること

## 3. やること

1. `FrameConstantAllocator`（仮称）を追加し、`Framework` が所有する。
   フレーム開始（`srvManager_->PreDraw()` の前後など、パイプライン実行前）で `BeginFrame()` を呼ぶ
2. `Object3d::Draw()` / `DrawGBuffer()` / シャドウ描画で、WVP とカメラの値を
   割り当てた領域へ書き、そのアドレスをバインドするように変える
3. `SkinnedObject3d` も同様に変える
4. **描画時のカメラは「その時点のアクティブカメラ」から取ること。**
   サブビュー描画中は `CameraManager::SetRenderCameraOverride()` で差し替わっているので、
   それを見れば自動的にビューのカメラになる
5. TASK-05 で入った `GameObjectManager::DrawTransparent()` の中の
   `obj->UpdateTransform()` / `object->Update(0.0f, ...)` は、この変更で
   **描画時に行列を作る**ようになれば不要になるはず。不要なら取り除くこと
   （描画経路で状態を書き換えるのは避けたい）。残す必要がある場合はその理由を報告すること

### 3.1 シャドウパスの注意

シャドウパスは本編で1回だけ描く（サブビューは本編のシャドウマップを共有する）。
シャドウ用の行列も同じ仕組みで割り当ててよいが、
**既存のシャドウの見た目が変わらないこと**を優先する。

## 4. やらないこと

- インスタンシング描画（`InstancedModelRenderer` 系）の定数の持ち方の変更
- マテリアル定数・ライト定数の割り当て方式の変更（ビューで値が変わらないので不要）
- パーティクル・スプライト・ラインの変更
- サブビューを実際に使う機能（カメラプレビュー等）の追加。**これは次のタスクで行う**

---

## 5. 受け入れ条件

1. 本編の見た目が**従来と変わらない**（不透明・半透明・スキニング・シャドウ）
2. 同じオブジェクトを2つのビューで描いたとき、それぞれのビューのカメラの行列で描かれる
   （コード上で、描画ごとに別領域が割り当てられていることを示せればよい）
3. GPU 実行中の領域を上書きしないことを、2.2 の確認結果とともに説明できる
4. 容量超過で落ちない
5. ONBOARDING の「タスク完了の条件」を全て満たしている
