今回追加・改修したGPUパーティクル、Niagara型モジュール実行基盤、GPU Ribbon、JSON保存、Selective Bloom、診断機能を、利用者向けAPIとエンジン内部APIに分けてまとめた資料です。前半はクラス別の大まかな変更点、後半はAPI契約と使用例を掲載します。

2. 実装で使用した主要技術

Pure GPU lifecycle

Spawn、Update、Alive判定、Compaction、描画引数生成をCompute Shader内で完結させます。毎フレームの粒子データやAlive CounterをCPUへ戻しません。

ExecuteIndirect

GPUが生成したD3D12_DRAW_ARGUMENTSをSprite/Mesh/Ribbon描画へ直接渡します。CPUは生存数を知らなくても描画できます。

GPU module program

EmitterのモジュールをGPU命令列とパラメータストアへコンパイルし、Compute Shaderで順番に評価します。Dynamic InputとCurve LUTもGPU側で参照します。

GPU events

Spawn/DeathイベントをGPU Bufferへ生成し、別EmitterのSpawn入力として接続できます。速度・色の継承と確率制御に対応します。

GPU Ribbon

Particle更新後にRibbon用Compute Passで頂点とIndirect Argumentsを構築します。Ribbon頂点のCPU生成やReadbackは行いません。

Selective Bloom MRT

通常Scene Colorとは別のR16G16B16A16_FLOAT Bloom Maskへ、指定したParticle/Objectだけを出力します。横・縦のGaussian Blur後にSceneへ合成します。

Pure GPUフレーム処理

Emitter設定更新→Spawn Prepare CS→Simulation CS→Compact / Convert CS→Ribbon CS（必要時）→ExecuteIndirect

Selective Bloomフレーム処理

Deferred Emissive GBuffer+Forward / Particle MRT→HDR Bloom Mask→Horizontal Blur→Vertical Blur→Scene Composite

4. GPUパーティクルの基本的な使い方

JSONをロードして再生

auto* particles = KCE::ParticleManager::GetInstance();

KCE::ParticleEffect* effect = particles->Load(
    "GpuFire",
    "./Resources/json/particles/gpu_fire.json");

if (effect) {
    particles->Play("GpuFire", KCE::Vector3{0.0f, 1.0f, 0.0f});
}
Load()は登録とロード、Play()は再生を担当します。同じ効果を頻繁に出す場合はWarmup()でプールを準備します。

EmitterをPure GPUへ切り替える

auto* emitter = effect->GetEmitter(0);
emitter->SetSimulationMode(KCE::SimulationMode::GPU);
emitter->SetMaxParticles(65536);
emitter->Play();

SetMaxParticles()は新Simulatorの作成成功後に交換するため、失敗時に旧容量を壊しません。交換前GPU resourceはFence連動の遅延破棄へ移されます。

GPU EventでEmitterを接続

auto* source = effect->GetEmitter(0);
auto* child  = effect->GetEmitter(1);

child->SetGPUEventSourceEmitterIndex(0);
child->SetGPUEventTrigger(1);             // 0: Spawn, 1: Death
child->SetGPUEventProbability(0.5f);
child->SetGPUEventVelocityInheritance(true, 0.75f);
child->SetGPUEventInheritColor(true);
child->BindGPUEventSource(source);

現状のPure GPU producerはSpawnとDeathです。Collisionは列挙値として予約されていますが、SetGPUEventTrigger()は2以上を拒否します。

6. Selective Bloom API詳細

共通設定型

enum class EmissiveSource : uint32_t {
    Uniform = 0,
    BaseTextureMask = 1,
    EmissiveTexture = 2
};

struct EmissiveSettings {
    bool enabled = false;
    EmissiveSource source = EmissiveSource::Uniform;
    Vector3 color = {1.0f, 1.0f, 1.0f}; // 各0..16
    float intensity = 1.0f;             // 0..64
    float bloomContribution = 1.0f;     // 0..1
};
Sourceの意味: Uniformは面全体、BaseTextureMaskはBase TextureのRGB、EmissiveTextureは専用Linear TextureのRGBを発光マスクにします。

Particle RendererでBloomを設定

KCE::EmissiveSettings bloom{};
bloom.enabled = true;
bloom.source = KCE::EmissiveSource::BaseTextureMask;
bloom.color = {0.15f, 0.65f, 1.0f};
bloom.intensity = 8.0f;
bloom.bloomContribution = 1.0f;

emitter->GetRenderer()->SetEmissiveSettings(bloom);
IRenderer API範囲・動作
SetEmissiveEnabled(bool)EmitterのBloom Mask出力を切り替えます。
SetEmissiveSource(EmissiveSource)無効な列挙値を拒否します。
SetEmissiveColor(Vector3)finite値だけ受理し、各成分を0～16へClampします。
SetEmissiveIntensity(float)finite値だけ受理し、0～64へClampします。
SetBloomContribution(float)finite値だけ受理し、0～1へClampします。
SetEmissiveSettings(settings)全項目をまとめて検証・設定します。NaN/Inf/無効Sourceを含む場合は変更しません。
SetEmissiveTexture(path)専用Emissive TextureをLinearとしてロードします。空・不正パスは専用1×1黒へフォールバックします。

GameObject / SpriteでBloomを設定

KCE::EmissiveSettings glow{};
glow.enabled = true;
glow.source = KCE::EmissiveSource::Uniform;
glow.color = {1.0f, 0.25f, 0.05f};
glow.intensity = 5.0f;
glow.bloomContribution = 0.8f;

object3d->SetEmissiveSettings(glow);
sprite->SetEmissiveSettings(glow);

Object3d、SkinnedObject3d、Spriteで同じ設定型を使用します。不透明Deferred ObjectはGBuffer RT3を経由し、Forward/Particle/SpriteはBloom Mask MRTへ直接出力します。

グローバルBloom

auto* post = sceneManager->GetPostProcessManager();
post->SetSelectiveBloomModeEnabled(true);

bool bloomOn = post->IsBloomEnabled();
bool selectiveOn = post->IsSelectiveBloomEnabled();

環境変数でも切り替えられます。

KCE_BLOOM_ENABLED=1
KCE_BLOOM_MODE=SELECTIVE   # LEGACYならScene輝度抽出方式

7. 描画・Render Target API

PostProcessManager

API説明
Draw(scene,output,selectiveBloomSource)Selective Sourceがあればそれを横Blur→縦Blur→合成します。なければLegacy Bright Passを使用します。
SetBloomRenderTargets(bright,blur0,blur1)Bright PassとPing-Pong Blur RTを登録します。
RenderBlurPass(input,output,horizontal)trueで横、falseで縦の13 sample Gaussian Blurを行います。
Resize(width,height)Viewport、Scissor、逆画面サイズ等を更新します。

ParticlePipelineManager

Sprite/Mesh用27順列とRibbon用27順列、合計54 PSOを初期化時に作ります。各BlendModeにつき以下の3種類です。

  • MRT + BloomWrite
  • MRT + Bloom書き込みなし
  • Bloom全体OFF用の単一Render Target
pipeline->SetSelectiveBloomOutputEnabled(selectiveOn);
auto* pso = pipeline->GetPipelineState(blendMode, emissiveEnabled);
auto* ribbonPso = pipeline->GetRibbonPipelineState(blendMode, emissiveEnabled);

RenderTexture

bloomMask.Initialize(dx, srv, width, height,
    DXGI_FORMAT_R16G16B16A16_FLOAT,
    {0, 0, 0, 0});

bloomMask.BeginRender();
// Deferred / Forward / Particle mask output
bloomMask.EndRender();

// 診断Copy等、特殊用途だけ明示遷移
bloomMask.TransitionTo(D3D12_RESOURCE_STATE_COPY_SOURCE);
通常フレームではFrameworkが状態遷移を管理します。ゲームコードからTransitionTo()を乱用しないでください。

8. JSON保存・ロード

RendererのemissiveにSelective Bloom設定を保存します。

{
  "renderer": {
    "type": "Sprite",
    "texture": "./Resources/circle2.png",
    "blendMode": 1,
    "billboard": true,
    "emissive": {
      "enabled": true,
      "source": "BaseTextureMask",
      "color": { "r": 0.15, "g": 0.65, "b": 1.0 },
      "intensity": 8.0,
      "bloomContribution": 1.0,
      "texture": ""
    }
  }
}
キー型意味
enabledboolEmitterのBloom対象指定
sourcestringUniform / BaseTextureMask / EmissiveTexture
colorobjectHDR RGB、各0～16
intensitynumber0～64
bloomContributionnumber0～1
texturestringEmissiveTexture時の専用Texture。空なら黒。

動作確認用: application/Resources/json/particles/tests/selective_bloom_pure_gpu_test.json

9. Particle Editorでの操作

  1. Particle EditorでEffectをロードします。
  2. 対象Emitterを選び、Rendererを展開します。
  3. Selective BloomでEnabledをONにします。
  4. Source、HDR Color、Intensity、Bloom Contributionを調整します。
  5. EmissiveTextureを使う場合は専用Textureを指定します。
  6. 保存し、再ロードして値と見た目が一致することを確認します。
見えやすい初期値: Source=BaseTextureMask、Color=(0.15,0.65,1.0)、Intensity=8、Contribution=1。

ブラーは横方向と縦方向の2パスです。細長く見える場合は、まず元Texture、Scale X/Y、Billboard Transform、Bloom Mask形状を確認してください。

10. 診断・性能計測API

ParticleDiagnostics

auto* d = KCE::ParticleDiagnostics::GetInstance();
d->SetEnabled(true);
d->Reset();

const auto& readback = d->GetCpuReadbackMemcpyStats();
const auto& counters = d->GetRuntimeCounters();

// Pure GPU試験では readback.averageBytes == 0 を確認
d->ExportToCSV(path, preset, "GPU", "Release",
               emitterCount, activeCount, "PASS");

CPU/GPU update、Upload、Readback、Renderer update/draw recordingを個別集計し、Pure/Hybrid GPU Emitter数、Module命令数、LUT sample数、descriptor概算も記録します。

Bloom GPU timestamp

post->BeginBloomGpuFrame(bloomOn, selectiveOn);
// Bloom Maskを生成
post->EndBloomMaskGpuScope();

const auto& t = post->GetBloomGpuTimings();
if (t.valid) {
    // t.maskMs, sourceExtractionMs,
    // blurHorizontalMs, blurVerticalMs, compositeMs
}

結果は前フレームFence完了後だけ読みます。Particle simulationのCPU Readbackとは別の、timestamp query診断です。

Bloom Mask診断

post->RequestBloomMaskDiagnostic(testId);
// 描画完了箇所でFrameworkが CaptureRequestedBloomMask(mask) を呼ぶ
const auto& result = post->GetBloomMaskDiagnostic();

試験専用R16G16B16A16_FLOAT Maskを要求時だけCopyし、平均/最大RGB energy、非ゼロpixel数、全画素finiteを検証します。通常実行ではReadback resource copyを発生させません。

12. 実装上の重要なルールと注意事項

Readback禁止

Pure GPU simulationではAlive CounterやParticle配列をCPUへ戻さないでください。描画数はExecuteIndirect、生存可能性はMayHaveLiveParticles()を使用します。

異常値防御

CPU APIはNaN/Infを拒否し、有限値を範囲Clampします。Shader側でも非finiteを検出して0へ置換します。

Resource lifetime

容量変更、Renderer交換、Effect破棄では、GPU Fence完了前にresourceやdescriptorを解放しません。

Emissive Texture

色Textureとは別にLinearでロードします。未指定時はemissive_black_1x1.pngを使用します。既存black.pngは発光用黒として使いません。

PSOとRT数

Bloom MRT PSOを1 RTへBindしないでください。Bloom全体OFFではSingleTarget PSOを使用します。

BlendMode

9モードを検証します。暗色系BlendではBloomの意味が異なるため、意図しない発光を避ける場合はContributionを0にします。
